Build worlds inside your game.

An in-game 3D level editor for GameMaker. Plug it into your project and build, edit, and save levels without leaving your game.

Get it on GitHub Quick start

Everything you need to ship levels

No external tools. Press F1 and edit right inside the running game.

  • In-game editing
    Toggle with F1; the gateway steps the live world while closed.
  • TRS gizmo
    Translate, rotate and scale with world or local axes and drag planes.
  • Outliner + Inspector
    Filter, rename (F2), focus (F), per-axis transform rows.
  • Undo / redo
    Snapshot history with selection restore.
  • JSON scenes
    One descriptor per placement. Save, load, new.
  • Directional shadows
    Per-light setup, preview and global toggle.
  • Snap + nudge
    Position/rotation snap and arrow-key nudge, all undoable.

Requirements

  • GameMaker with GMRT 0.22.4 (from the Package Manager)

Quick start

1. Import the editor package - drag gm3d_editor.yymps onto the GameMaker IDE to import the scripts. You also need GMRT 0.22.4 (Package Manager), which provides GM3D_* and ImGui.

2. Add an object with 5 events (full working example in objects/oEditor). Load each model once, register it with a unique name:

// Create
gm3d_editor_init(id, {
    scene: global.my_scene, // your live GM3D_Scene
    cam: global.my_camera,  // gameplay camera (editor flies its own copy while open)
});
gm3d_editor_asset_add("Tree", my_load_model("models/tree.glb"));
gm3d_editor_track("asset", "Tree", my_tree_node, "Tree");
gm3d_editor_track("light", "", my_sun_node, "Sun");

// Step
gm3d_editor_step();
if (!gm3d_editor_is_active()) my_game_step(); // live world only while closed

// Draw
gm3d_editor_prerender();
my_game_render();
gm3d_editor_postrender();

// Draw GUI
gm3d_editor_draw();

// Clean Up
gm3d_editor_cleanup();

While the editor is open it owns the camera and the scene: pause your own simulation and resume it in on_close. Nodes your game spawns itself can join Scene/Inspector/save/undo via gm3d_editor_track(kind, asset, node, label?), where kind is "asset", "light", "camera" or "environment".

Scene file format

{ "version": 1, "nodes": [...] }, one descriptor per asset placement:

{
  "kind": "asset",
  "asset": "Tree",
  "name": "Tree 2",
  "position": [1.0, 0.0, 2.0],
  "rotation": [0.0, 0.0, 0.0, 1.0],
  "scale": [1.0, 1.0, 1.0],
  "flags": { "castShadows": true, "receiveShadows": true }
}

Lights, cameras and the environment carry a light / camera / environment sub-struct (angles in degrees, colors as [r, g, b] 0-255). Directional lights can also carry shadow: { enabled, resolution, distance, normalOffset }.

Shadows

Directional lights support shadow mapping, editable in the Inspector under Shadows; selecting a shadowed light draws its coverage box, and the toolbar Shadows button toggles preview without touching saved values. Every material needs both a Forward and a Shadow shader, assigned per live instance — spawnInto clones do not inherit source assignments, so assign them in your spawn hook. Use the sStatic / sAnimated (+Shadow) shaders from this project.

In-game loading (no editor)

gm3d_load(scene, fname, models) spawns a saved scene into any live GM3D_Scene. Load and freeze each model once, then pass them as { asset: model } — the asset field is the key into this struct, name is just the instance label:

var _models = {
    Tree: my_load_model("models/tree.glb"),
    Rock: my_load_model("models/rock.glb"),
};
var _rep = gm3d_load(my_scene, "__gm3dEditor/scenes/level1.json", _models);
// _rep = { placed: 9, failed: 0 }
// After loading, assign Forward+Shadow shaders per spawned node (see Shadows above).
